# 0.0.6a.R19-HF12 — control-plane hardening (pre-release)

Download the **UPDATER.zip** asset for an existing HF11 / Node R13 installation.
The source-code archives are for development. Stop Manager, gateway and workers,
extract the updater separately, and run `APPLY_UPDATE.bat`. Keep its backup path.
This release changes Manager R19 and its launcher; Node R13/Gateway R19 are unchanged.

- Damaged administrator credentials now stop startup instead of reopening setup.
  Login throttling follows source IP across connections, credential request size is
  bounded, and remembered sessions cannot survive a password change via stale disk
  state. Existing remembered sessions are invalidated once; sign in again.
- Missing vault keys stop recovery instead of generating a replacement key. Failed
  security-file writes leave in-memory state consistent with the reported failure.
- JSON decoding preserves Windows paths and literal escapes, and rejects malformed,
  duplicate-key or excessively nested input.
- Journal appends handle partial writes; uncertain writes stop further commits.
  Compaction forces snapshot data before replacing it, and only truncates recovery
  logs after directory metadata can be synchronized. Corrupt/incomplete journals
  fail closed and retain evidence. On Windows, retained WALs can grow; monitor disk.
- Chunk invalidations coalesce only while queued, so continued mutations cannot
  suppress every later notice. Pending and in-flight frame counts are bounded.
  Message IDs are unique across manager processes so delayed acknowledgements cannot
  discard new frames after restart. Durable block commits validate authority under the region transition lock and
  reject expired leases.
- Late worker heartbeats and registrations cannot mark a stopped worker ready or
  override stop, kill or retirement fences.
- The v2.2 reference ledger rejects illegal replay transitions even when record
  checksums are valid. This is still a model, not the Minecraft runtime integration.
- CI builds/tests both platforms before release. The updater verifies hashes,
  backs up every replaced file, supports rollback, and blocks normal startup after
  an interrupted update. It does not overwrite worlds, keys or active config.

This is a staging candidate, not production certification. Live multi-worker
acceptance, host-crash recovery, transactional epoch persistence, full worker
storage fencing, and per-worker authenticated transport remain release gates.
See `docs/audits/2026-10-05-hardening.md` in the matching source tag for scope.
