# Foundations Cluster 0.0.6a.R19-HF13

Repairs Windows gateway startup failing with `R19 bridge class missing: SeamlessConfigSessionHandler.class` after a GitHub source download.

- Ships the complete compiled R19 Conduit bridge and Velocity plugin in the updater, together with source and the bridge license. HF12 only shipped the control plane.
- Fresh source startup installs a full isolated JDK 25 when compilation is needed, then builds both artifacts against Conduit 1.8.0. Installed updater binaries work with the isolated Java 25 JRE already downloaded.
- Applies and hash-verifies every bridge class in a staging proxy JAR before replacing the runtime. Includes both tag and NeoForge configuration helpers.
- Removes the startup dependency on a Velocity Maven snapshot and Gradle for these gateway artifacts.
- Preserves HF12 control-plane hardening, backup/checksum/rollback guards and operator data. Gives a specific error for an uninitialized source folder.
- CI builds the real gateway on Windows, exercises fresh-source and precompiled bootstrap paths in folders with spaces, runs the handshake/tag/declaration regressions, and tests updater transactions before release.

## Install

Stop Manager, gateway and all workers. Download and extract `FoundationsCluster-0.0.6a.R19-HF13-UPDATER.zip` separately, then run `APPLY_UPDATE.bat` against your existing Cluster folder. Restart normally. You do not need another full source download.

Accepts existing HF11, HF12 or HF13 Manager installations with the Node R13 baseline. Includes HF12 hardening. Worlds, credentials, journals and active configuration are preserved; Node R13 is unchanged. Keep the updater and the printed backup path for rollback. Use the matching old updater to restore old HF12 backups.

This is a bootstrap/packaging fix; existing R19 gateway protocol behavior is unchanged. Tests use real Conduit classes with fixture downloads and do not prove live multiworker Minecraft acceptance or production readiness. World Replication v2.2 remains an isolated model.
