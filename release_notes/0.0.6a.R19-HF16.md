# HF16 — Worker controls and recovery hardening

Manager API R19 / package HF16 / Node R14 / gateway R19. Pre-release.

## Operator controls

- Add a top-bar Shutdown Cluster button, visually separated from Restart Servers.
  Restart Servers requests rolling Minecraft worker restarts while Manager and
  gateway stay online. Shutdown Cluster exits Manager, closes its owned gateway
  and requests shutdown of managed workers. External processes are not stopped.
- Open worker details by clicking non-interactive cells anywhere in a worker row,
  on both the Dashboard and Workers pages. Enter and Space also open a focused row.
- Add adjacent Restart, Stop and Kill buttons. Stop is graceful and evacuation-aware;
  Kill is an emergency force-stop with an explicit unsaved-world-data warning.
- Keep action clicks separate from row navigation, preserve row focus on refresh,
  retain controls through filtering/sorting, reject duplicate in-flight requests,
  and disable unavailable, external, stale or shutdown-blocked actions.

## Included recovery fixes

Includes the merged player-ledger FCP2 framing/recovery work and the Manager
support-archive metadata/retention race fix from PR #1. The reference ledger is
not a deployed Minecraft inventory adapter. Remote Survival breaking and placement
remain disabled; the player/chunk/entity and two-worker seam gates remain open.

## Install

Stop Manager, the gateway and all workers. Extract the updater separately, run
APPLY_UPDATE.bat and select the existing installation. Restart normally and use
Ctrl+F5 in the dashboard. The updater accepts HF11 through HF16 and stages Node R14
for the existing backup-preserving template/worker synchronization path.

Worlds, profiles, security, journals, active configuration and seamless mode are
not updater payloads. Keep the updater and its matching update-backups directory
for rollback. Later Node/template synchronization and gateway runtime patches
have their own backups; never delete a world to resolve a version mismatch.

## Validation scope

Local control-function tests: 48 passing checks with inert API/DOM fixtures.
Local Chromium tests: 36 passing checks against production HTML/JS and simulated
worker responses, including desktop/mobile layout, click isolation, keyboard
navigation, filtering, sorting, disabled states and separate endpoint dispatch.
No real worker process was stopped by these browser tests.

Windows/Linux CI remains the release gate for the full repository, the real
NeoForge GameTests, gateway build and Windows updater apply/rollback transactions.
The recovery baseline passed those gates before PR #1 was merged. Consult the
workflow for this exact HF16 candidate before describing it as release-validated.
