# HF15 — Survival interaction groundwork / Node R14 (pre-release)

**Remote Survival breaking and placement remain disabled.** This is the tested
Spike A/C groundwork build, not the completed Survival feature.

- Adds a player-aware NeoForge authority break executor with ownership, reach,
  block and full-tool preconditions; it is not exposed to live remote requests.
- Adds an authority result journal and real NeoForge tests of tool wear, drops,
  cancellation, placement/use, actor differences, durable result NBT and a
  chunk mutation/operation-marker serialization round trip.
- CI now builds and tests the actual Node on Windows and Linux.
- Node R14 shows a throttled explanation when a Survival edit is rejected in a
  replicated area. Operators can run foundations_interaction_status.
- Fixes the Linux Node build script's undefined SCRIPT_DIR.
- Includes HF12 security/recovery fixes, HF13 gateway artifacts and HF14 Test Lab
  fixture repair. Manager API and gateway protocol stay at R19.

## Install

Stop Manager, gateway and every worker. Extract the updater separately, run
APPLY_UPDATE.bat, select the existing installation and restart normally.
The updater stages the built Node R14 JAR; Manager installs it into the configured
template and synchronizes stopped workers using its existing backup-preserving
upgrade path. No Gradle download is required for an updater installation.
Refresh the dashboard with Ctrl+F5.

Accepts existing HF11–HF15 installations. Worlds, profiles, security, journals,
active configuration and seamless mode are preserved. The separate test mod and
disposable fixture world are not in the updater.

## Validation and limits

Windows/Linux release gates include portable Java/UI/HTTP regressions, real
Minecraft 1.21.1 / NeoForge 21.1.250 GameTests, gateway/bootstrap tests and Windows
updater apply/rollback tests. Game tests are single-process fixtures, not live
client, protection-mod or multi-worker crash certification. See
docs/status/WORLD_REPLICATION_V2_2_SPIKE_A_C_2026-10-09.md for the evidence and
remaining gates.

Keep the updater and backups. Updater rollback restores staged payload files.
Node copies installed by a subsequent Manager startup and gateway runtime
patches are separate: restore matching Node/template backups when reverting to
an older Manager. Never delete a world to resolve a Node version mismatch.
