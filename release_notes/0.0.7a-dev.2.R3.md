# Foundations Cluster 0.0.7a-dev.2.R3 — Automatic Cow/Item Discovery (Development)

**Node R17 / Manager R19 / gateway R19 / Minecraft 1.21.1 NeoForge 21.1.250.**

R3 adds bounded, automatically enabled source-side entity discovery paired with explicit connected-operator remote view consent. It removes the need to pair each supported cow or dropped item by hand. The Manager forwards nearby subscribed viewer positions to authoritative sources. The Node scans **already-loaded** entities, checks source readiness and exact UUID, and sends bounded, read-only vanilla presentation frames. The Manager verifies current ACTIVE region ownership before relaying ephemeral observations; no discovered pairing is persisted as an entity spawn/recovery instruction. Expiry, duplicate/stale sequencing and UUID collisions remain fail-closed. Manual Rev2 pairing stays available for diagnostics.

The transport protocol adds a versioned automatic flag and bounded viewer interests. Both the Manager and Node require this exact Node R17 version, and the old protocol is intentionally not mixed during a rolling install. No new mod identifier, registry or client mod is added; frozen design is unchanged. Source scan is bounded to loaded cow/item entities and defaults to auto-discovery ON on fresh R3 workers; operators can stop a source with `/foundations_entities auto off` or resume with `auto on`. Destination operator view consent is still required via `/foundations_entities view on`. Auto state does not persist across restart. Disabling or losing source readiness removes previews without creating a gameplay entity.

**Important limits:** This is **NOT** finished generic modded-entity mirroring, entity ownership migration, pickup transactions or remote Survival. It is still a source-bound, display-only experimental feature. No claim of zero transition hitch or connected-client smoothness is made. Only one worker simulates the actual entity; R3 never creates, saves or interacts with a duplicate server-side entity. We must still validate automatic player-facing operation, mod adapters, durable generation-fenced ownership transfer and crash recovery before calling the feature complete.

Windows/Linux CI must pass portable protocol and Manager tests, real NeoForge GameTests, gateway compilation, and Windows updater apply/reinstall/rollback on this exact revision before publishing. The `ENTITY_VIEWS_GUIDE.md` in the updater contains safe test instructions. Preserve operator worlds, profiles, credentials, runtime journals, active configuration and preexisting reports. Test on a backup copy, stopping all processes first; keep the backup path for rollback. Prior HF16/dev.1/dev.2/R2 assets remain immutable.
