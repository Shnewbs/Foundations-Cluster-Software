# Foundations Cluster — R3 Automatic Entity Discovery Test

**Build:** `0.0.7a-dev.2.R3`; **Node:** `0.0.6a.R17`; Minecraft 1.21.1, NeoForge 21.1.250.

This development build removes **manual pairing for automatically supported entities**. It **does not** implement full ownership transfer or generic modded entity replication. Automatic source-side discovery defaults **ON** for supported loaded cows and dropped items, while **remote viewing remains OFF** until a connected operator explicitly runs `/foundations_entities view on`. An operator can stop discovery on A with `/foundations_entities auto off`; that switch is not persistent across restart.

## Installation

1. Stop the Manager, gateway and **all** workers. Make a complete backup, or use a test copy.
2. Extract the versioned `FoundationsCluster-0.0.7a-dev.2.R3-UPDATER.zip` away from your install and run `APPLY_UPDATE.bat`. Give it your existing cluster root. Retain the backup directory.
3. Start normally and confirm **package R3** and **Node R17 on every worker**. Ctrl+F5 refreshes the dashboard. All prior HF16 controls remain.
4. If a worker is out of date, stop and fix the version mismatch; do not remove world files or force unsupported cross-version replication.

## Test with two Minecraft clients

Run two workers with the same cluster world identity, modpack, dimension and compatible registry setup. Use an isolated copied world with at least one region ACTIVE and hydrated on worker A. A should be able to tick the already loaded cow/item. If both layers have independent native animals in the same location, keep them identified separately; R3 never deletes or merges native UUIDs.

On **source worker A**, join as an operator and check:

```text
/foundations_entities status
```

Auto-discovery is already enabled on a fresh R3 worker; no `/foundations_entities pair` or `auto on` command is required. If you previously ran `auto off`, use `/foundations_entities auto on` to resume discovery. Viewing remains separately permissioned and opt-in on the destination.

On **destination worker B**, join as an operator, stand in the same dimension near the source cow's canonical world coordinates, then enter:

```text
/foundations_entities view on
/foundations_entities status
```

The Manager tells the source where opted-in remote viewers are. The source scans **already loaded** authoritative cow and dropped-item entities in range, sends their exact UUID and state, and B displays packet-only copies. Allow a moment for the initial interest round-trip. Move the real cow on A and observe its position/movement on B. Repeat with a dropped item. Taking the real item on A should remove B's preview. A fake B-side preview must not be attackable or collectible. Auto tracking should stop when the viewer walks away or the source goes offline; no entity should be regenerated by a saved preview binding.

```text
/foundations_entities auto off
/foundations_entities view off
```

`auto off` is a source-side emergency/debug switch; a new server process resets auto-discovery to ON. `view off` revokes this connected player's remote preview consent.

Run `/foundations_entities status` on both workers and, if needed, the Manager `/api/entity-views/status` page (administrator access). Send outputs, any pairing/UUID collision diagnostic, and the approximate location/dimension of a mismatch. Prefer a screen recording for the already-observed transition hitch; packet preview experiments do **not** prove smooth client transitions.

## Safety bounds and limits

- **Automatically supported:** vanilla cows and dropped item entities. This is a safe initial compatibility subset; unsupported vanilla and modded entities stay untouched and are not silently paired. UUIDs already exist on native entities; no manual UUID assignment is required.
- **Display only:** no destination Minecraft world entity, AI, physics, world save, damage, loot or pickup. The real entity stays on A. No source world object is created from saved pairing metadata.
- **No world traversal:** scans only loaded entity indexes; never loads a missing chunk to find an entity. Up to 8 temporary nonpersistent source tickets are retained while an already-loaded entity has interested viewers.
- **Bounds:** 24 automatic source observations, 8 manual diagnostic pairs/source, 32 total remote views/viewer, 8 interest positions/source, at most 4 served viewers/worker, 64-block view distance, 200 ms target update, 1.5-second stale expiry and 15-minute viewer consent. Overflow is hidden/deferred rather than duplicating simulation.
- **No automatic operator consent:** `/foundations_entities view on` is still required in this development release. Source automatic discovery does not need manual pairing of individual mobs/items.
- **No ownership transfer:** if authority leaves A, the preview disappears rather than promoting a fake B entity. Modded entities, passengers, leashes, vehicles, full entity-state transfer, cross-worker item pickup and generation-CAS/tombstone recovery remain future acceptance gates.
- **No cross-worker Survival editing:** the existing intentional safety restriction stays in place. This update does not fix it.

Passing GameTests proves encoded metadata and server-side protocols, **not** connected-client appearance or crash-safe cross-worker gameplay. Never use this preview as evidence of durable, automatic full-entity migration.
