# 0.0.7a-dev.2.R3 — automatic interest-driven entity presentation

Scope: Minecraft 1.21.1 / NeoForge 21.1.250, Node R17, Manager/gateway R19. This dev release automates discovery of already-loaded cows and item entities rather than operator pairing each UUID. Exact native UUID, dimension, position, velocity, facing and synchronized metadata are retained. The existing protocol now carries consented remote viewer interest to source owners. Manager rejects automatic samples without deterministic binding or current ACTIVE region authority. No preview state is persisted for resurrection. Safe, bounded visibility-only updates never instantiate a destination server entity.

Source automatic discovery is ON by default on R3 workers and can be disabled per process with `/foundations_entities auto off` (or re-enabled with `auto on`). Remote viewing stays OFF until each connected destination operator grants 15-minute consent via `/foundations_entities view on` on B. Manual pairing remains for debugging only. Discovery is bounded to 24 automatic entities per source per refresh, 8 remote viewer centers, 4 viewer recipients and 8 temporary source tickets. Missing/unsupported native entities remain untouched.

Tests: Existing 59 Minecraft GameTests plus 4 new loaded-source discovery GameTests; actual counts only trusted after execution. New synthetic source-authority/interest tests, wire framing tests and HTTP Manager auto-mode tests; test outputs are not joined-client proof. No generic modded compatibility or real entity ownership CAS. The existing user-observed pause remains unoptimized. Remote Survival remains gated. Frozen design unchanged. Future V0 scope must include cow A -> B -> A full-state, Manager generation compare-and-set, tombstones, pickups, inventories and process-kill matrix, with real connected-player acceptance.
